因此，**该响应不能直接作为本案例的完整历史版本库**。本轮没有穷尽东方财富全部服务或其他参数，不能据此断言其所有产品或内部数据库从未保留旧版。一次成功也不证明接口稳定性、商业使用许可或全历史覆盖。

给 `NOTICE_DATE` 一律增加 90 天不能自动修复这个问题：不同指标可能在更晚时候再次修订，而当前行没有告诉我们每个值的首次出现日期。`UPDATE_DATE` 也无法还原已不在响应中的 31.27%，更不等于本次更正的 2025-05-30。固定延迟只能处理已知版本公开后的处理假设，不能替代版本历史。

## 4. 对项目数据规则的具体影响

1. 同一公司、同一报告期不能只有一个覆盖更新的财务行。原披露值、更正值、版本对应的公开日期和原文定位应分别留存；API 数据商的当前行是另一个来源记录。
2. 首次公开日期与版本必须绑定。例如，本案例的“公告报告 ROE=7.92%”不能只因当前 API 同行带有 `2025-03-21`，就被认定为 3 月可知。
3. 原披露值存在错误时，不要求模型盲目使用错误数值。可以按事前规则标记异常、排除该特征，或用当时已公开基础科目按固定公式另算指标。另算指标须保留自己的公式和来源，不能借后来的更正答案倒推后再称当时已知，也不能与公司公告的加权 ROE 混为同一字段。
4. 仅有日期时，仍按 [数据质量要求](../DATA_REQUIREMENTS.md)采用预先冻结的保守可用延迟；本次下载时间是 2026-10-15，不能回填为 2025 年采集。
5. ABC 对照共用相同的财务版本重建规则。文本组若可见更正公告，数值组也应允许在同一可用时点更新对应财务输入；不能给某一组提前看到修订结果。
6. 若某段历史只能获得当前修订行，标记并阻断依赖该字段的正式历史预测验收；可继续做接口演示、缺失回退、无需该字段的研究，或缩短至可证实区间。
