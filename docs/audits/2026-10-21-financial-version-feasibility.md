审计日期：2026-10-21，Asia/Shanghai；客户端日期与本轮机器时钟一致。状态：**一个公司、一个报告期的目录—文件—已核对指标链完成有限验证；没有验收全历史财务版本库。** 本轮仅只读查询公开资料并记录结果，未安装或运行 SDK，未编写系统代码、注册或付费。

## 1. 这次推进了什么

上轮已证实同一期年报的首次披露 ROE 为 31.27%，更正版为 7.92%，当前结构化接口却把更正值与首次公告日期放在同一行。本轮继续验证：是否能通过公开目录重新发现三份不同材料，而不只依赖事先知道的 PDF 链接。

**实测证据：可以在本样本中分别检索到首次年报、更正公告、更正版年报。** 巨潮公开历史公告目录返回 5 条相关记录，另两条是首次及更正版的摘要；三份全文材料的公告 ID 和 PDF 路径均与上轮记录一致。本轮再次下载这三份 PDF，字节长度与 SHA256 全部与 2026-10-15 的采集结果一致。

这给出了可行路径：先用官方公告目录识别材料，再保存独立版本和原文证据，最后生成相应时点允许使用的数值。它仍需要我们明确版本关系、时间语义和质量检查；**目录接口不是已经做好的“按历史当时已知信息查询”的财务数据库。**

本轮[结构化证据](2026-10-21-financial-version-feasibility.json)保存完整的有限目录解析结果、请求参数、请求/响应时间、原响应哈希、三份文件哈希与派生时间字段。目录原始字节及 PDF 未作为仓库附件保存；不能仅靠本 JSON 离线重算原始响应或 PDF 的哈希。

## 3. 时间字段不能一律升格为首次公开时刻

**实测证据**：同一个字段中，首次年报恰为午夜，更正材料则带不同的小时、分钟和秒。字段采用毫秒数值格式，不意味着每一行拥有毫秒级真实公开时间。午夜也不能证明 3 月 21 日开盘前就可使用。

**未决**：本轮没有取得该字段在所有时期、所有发布渠道上的生成语义说明，没有验证其是否为文件上传、目录上线、公告标记或全市场首次公开的时间。更正材料的秒级值应原样保存，但不能把“目录给出这个值”改写为“首次公开精确到这一秒已经认证”。不同材料时间相差数秒或数分钟，也不意味着模型能够在当时完成下载、解析、校验和交易。

**研究默认建议**：先区分日期证据等级，再讨论重建。3 月首次披露日期有更正正文明确回述；5 月目录日期与文件路径、公告落款相吻合，当前适合作为日期级重建假设，尚未独立认证历史上线时间或公开上界。原始秒级字段全部保留，待核实其语义。采用日期级假设时，从对应日期结束加预登记处理延迟后，按正式日历和共同决策批次考虑纳入，并记录假设身份；不能把试算准入写成历史时点已经认证。前瞻运行还必须满足实际已采集、解析校验完成。详见[数据时序政策](../ASOF_DATA_POLICY.md)与[数据要求](../DATA_REQUIREMENTS.md)。这不是“所有资料统一延迟若干天就安全”：版本本身必须先绑定正确。

对于本例，已经足以演示原版与更正版的不同使用批次，并讨论保守的日频或周频规则，无须为了教学强求分钟级首发认证。正式准入仍须按上述等级核查日期证据，不能让处理延迟掩盖其不确定性。保守约定可能错过一部分更早可得的信息，也不能冒称准确重演所有交易者当时的信息集。

## 4. 版本留存建议及建模意义

以下为**研究默认设计建议，尚未实现**：

1. 以来源、公告 ID、文件哈希识别材料版本，保留证券身份、报告期、材料类型、URL、原始时间字段、时间语义与精度、采集时间及原文位置。相同 URL 后续若变更内容，生成新内容版本，禁止覆盖旧文件。
2. 版本关系另记证据：更正公告指向哪份报告，哪些指标发生变化，是否涉及财务报表重述。本例属于年报披露指标等内容更正，公司明确不调整财务报表；不能扩大为净利润或营业收入重述。
3. 数值记录必须指向材料版本及原文页码。31.27% 与 7.92% 分别保留，按各版本可用时间切换。今天的 API 当前行只能作为当前来源记录，不能替代早期版本。
4. 对有问题的原披露指标，可以依事前规则标记异常、缺失或用当时已公开基础数据另算明确命名的指标；不能用后来更正答案反推一个“当时已知”的特征。
5. 正式实现时，原文件和目录响应应在许可与保存策略确认后归档，哈希用于检测变更，提取器/公式版本用于复现。**只有哈希、没有原文件，不足以保证离线复现。** 本轮审计只保留有限摘要和解析目录，没有建立归档系统。

金融意义是保证模型在 3 月面对的是 3 月能够知道的信息，而不是事后更完整、更正确的答案。B 数值组和 C 文本组共用同一版本可用规则；C 不能提前使用更正公告，B 也不能在更正前得到改后数值。这样研究到的增量才可能来自信息处理能力，而非数据泄漏。

## 5. 失败、限制与下一步

一次早期目录测试返回 0 条，当时中文关键词经本机 PowerShell 管道发生编码损坏，且只传了证券代码而未组合 orgId。该结果属于请求构造问题，不能作为巨潮缺历史数据的证据。修正后有限查询返回 5 条。另有不完整股票页 URL 返回 HTTP 200 的“页面不存在”正文，以及两个错误 GitHub 路径返回 404；均已在 JSON 单列，不混入数据能力结论。

已完成：一个报告期的版本目录检索、与上轮原文对应、三文件两次采集哈希一致、混合时间精度识别，以及版本存储的具体建议。

尚未完成：其他公司和报告期、不同重述类型、证券更名/退市目录覆盖、2013—2025 全量覆盖率、关键词漏检率、超过一页的结果完整性、首发时间语义、长期文件不变性、服务限制与再分发许可。两次采集一致，只证明这两次内容相同；不保证文件永远不变。

下一步准入方向：允许这个已核对案例用于版本处理的教学和后续小样本演示；正式财务特征研究仍需覆盖检查、原件保存策略和统一时序规则通过。没有可证旧版的字段应暂缓正式历史验收或回退至不依赖它的特征，不能为凑齐特征数量而使用当前更正行。
