## 3. 拟定模块职责与产出位置

以下 **MOD 编号为规划中的逻辑模块**，尚未选择框架、数据库或部署形式；不意味着微服务，也不代表目录已创建。实际路径由 T-03 确定，并回写开发计划的“实现/测试路径”列。

| 模块 | 负责什么／输入输出 | 不承担什么 |
| --- | --- | --- |
| MOD-DATA | 上游只读适配、证券身份、原件/快照、标准化、质量与按时点查询 → 证据及准入结果 | 不自动把最新值视为历史可用，不负责预测 |
| MOD-LEDGER | 资金流、成交、公司行动 → 头寸、应收、现金、净资产与单位净值 | 不从预测制造成交，不把分红到账重复记收益 |
| MOD-POLICY | 配置、账户状态、风险估计 → 额度、限制、复审/冻结和允许动作 | 不训练收益模型，不自行改变用户边界 |
| MOD-EXEC | 合法订单意图、市场/费用规则 → 拒绝原因、模拟成交/未成交事件 | 不保证真实成交；真实券商适配单独验收 |
| MOD-RESEARCH | 准入特征、成熟标签、配置 → 模型/风险估计、组合候选、实验报告与运行记录 | 不把统计分数直接当交易权限 |
| MOD-TEXT | 原文与证据 → 抽取字段、关联候选、引用、未知与复核项 | 不靠语言流畅度证明收益，不执行原文中的指令 |
| MOD-UI | 证据/账户/实验 → 阅读、比较、检索、审核和干预界面 | 不绕过后端准入与风控，不将代理显示为精确值 |
| MOD-OPS | 运行配置、计划和状态 → 日志、监控、失败恢复、备份与部署记录 | 不因重启清除历史表现，不默认开启实盘 |
| MOD-BROKER | 后期获授权的订单与券商接口 → 幂等提交、成交回报与对账 | 不由数据或回测通过自动获得实盘权限 |

建议依赖方向：数据/证据 → 特征及风险 → 组合候选 → 政策检查 → 执行 → 账本；UI 读取证据并提交有记录的用户动作；运行管理覆盖全链路。该方向来自既有理论职责，具体调用方式待 IF 契约冻结。

## 4. 接口现状与下一步必须补的契约

上游腾讯/新浪、中证、巨潮、东方财富、BaoStock 的请求只形成有限审计证据；Tushare 等部分仅文档能力。它们不是已选定的生产供应商，更不是已实现的内部接口。具体参数保留在 audits/，开发时通过适配层隔离上游变化。

| 候选内部契约 | 最小语义与需要定义的失败情况 | 消费方／冻结任务 |
| --- | --- | --- |
| IF-01 证据与数据记录 | 稳定对象/来源/原文定位、观察与公开证据/采集时间、单位、版本、覆盖与质量；明确空、冲突、修订、原件缺失 | MOD-DATA → TEXT/UI/RESEARCH；T-01、T-04 |
| IF-02 历史准入查询 | 对象、字段、截止、用途、数据版本 → 允许值＋依据或拒绝/降级原因；日期上界、成员生效、前瞻处理完成不同语义 | MOD-DATA → POLICY/RESEARCH；T-01、T-04 |
| IF-03 账本事件 | 事件 ID、账户、证券、金额/数量、时间、原因/来源；成交、应收、支付、资金流分型；重复、乱序、更正、舍入待定义 | EXEC/行动处理 → LEDGER；T-01、T-05 |
| IF-04 订单与风险决定 | 意图、信息截止、账户/规则版本 → 允许/拒绝/降额及原因；有限减险许可、具体事件复审证据与批准/失效可追溯；成交回报不可与意图混用 | POLICY ↔ EXEC/BROKER，UI提交有记录的决定；T-01、T-06、T-09 |
| IF-05 特征、标签与预测 | 公式版本、证券/期间、截止、证据 ID、缺失原因；标签成熟时刻、模型训练版本、风险期限 | TEXT/DATA → RESEARCH → POLICY；T-02、T-07、T-08 |
| IF-06 实验与运行清单 | 代码/文档/数据/配置/模型版本、尝试 ID、种子/环境、假设、检查及产物位置；失败也留存 | 全模块 → RESEARCH/OPS/UI；T-02、T-03、T-10 |

以上是**待确认的契约清单**，不是 JSON Schema、REST API 或数据库设计。字段类型、可空性、主键、精度、幂等、错误分类、兼容迁移和权限尚未补齐，不能直接宣称达到编码规格。G-01、G-06、G-12 分别追踪。
