# A 数值精度、事件身份与失败处理契约

更新：2026-11-03；版本v0.1。依据Git `ca71ee6`的投资政策v0.3、A账本v0.5、费用v0.3、额度v0.2、风险v0.2及AD-01至AD-07。D-038为助手在现有授权内提出的技术方案，**已设计、待A全链路联合冻结**；不改变用户投资偏好，不选定工程栈，不启动系统代码、账户或实验。

主责：跨模块数值语义、事件业务键、原子变动、重复/乱序/更正与错误动作。金融公式及批次分别由[账本](A_LEDGER_AND_EXECUTION.md)、[费用](FEES_AND_GAP_PROTECTION.md)、[额度](WEEKLY_QUOTA_AND_REBALANCE.md)、[风险](RISK_STATES_AND_RECOVERY.md)主责；来源准入由[数据契约](DATA_CONTRACTS.md)主责。关联R-07/09/12/13/15/17，MOD-DATA/LEDGER/POLICY/EXEC/OPS/UI，IF-01/03/04/06；当前T-01/AC-01，供T-04/05/06/09/10/11及对应AC使用。PE-01至PE-20是合成验收预期，尚未执行系统测试。

## 1. 范围和设计理由

仅覆盖A的人民币、单只股票ETF、现金、现金分红、现有统一成本及S1研究情景。普通成交为整手全量或零成交；分笔领域例检查增量账本，不声称支持券商分笔撮合。拆并份、实物转入、全清户、退款冲正、真实税费/尾差及券商回报留相应缺口；遇到路径内必需但不支持的事件，应阻断而非忽略。

核心不变量：同一经济事实只改变账户一次；提交中断不能只记持仓而漏记费用/额度；显示舍入不能改变交易资格；新数据不能悄悄改写过去决定。十进制也可能受计算上下文舍入影响，不能仅把类型命名为Decimal就宣称精确。专业依据与实际阅读范围见[参考资料第20节](../REFERENCES.md#20-2026-11-03-精度与事件契约依据)。

本版借鉴精确数值和事务/幂等原则，采用单账户有序处理的最小契约；不因此要求消息队列、微服务、云产品或整套事件溯源框架。

## 2. 数值与传递格式

| 对象 | 规范语义／运算 | 禁止或失败行为 |
| --- | --- | --- |
| 原始数值 | 保存来源原文、单位与精度；规范金融量使用有限十进制字符串，解析为精确十进制系数和尺度或等价精确值 | 不先转二进制浮点再转回；不从已经舍入的展示值恢复输入，不把未知补0 |
| q、权利数量e、订单Q | 整数份额；持仓/可卖/许可上限非负，订单方向另记，公式δ才带正负 | 合法整手按有效规则校验；数量向下取整只作用于非负绝对数量，不对负卖单直接floor |
| 原价P/O、成交p、tick | 元/份；原价及实际模拟成交须为有效tick倍数。相容参考价P_ref允许保留除息换算后的更细精度 | 源价格不符tick先报错，不静默修成合法价；只有既有滑点和保护价步骤允许方向舍入 |
| C、实收实付、已确认佣金 | 本研究情景以元计、精确到分；可等价保存整数分，接口仍给单位 | 佣金沿用累计计算后到分再作差；不逐条回报重收最低额，不把默认半偶舍入当现有恰半向上 |
| 成交本金B/R_s、相关费用L | 当前合法整手及tick的乘积应能精确到分；保存本金、费、未付余额及各自关联 | 不满足本范围分精度的特殊成交不能无声四舍五入；未来真实回报保留事实另核适配，不编造精确结算 |
| 理论权利e×d、估值qP、V、F/H、W/Z/T | 保留精确有限十进制，只有规定步骤舍入；W沿用floor_cent(0.05×V_anchor)，计算5%后向下到分 | 不统一截到分、不把W改成四舍五入或向上到分；F等支付承诺依原公式，负可用额仍按账本语义解释 |
| U绩效份额 | 约分后的整数分子/正整数分母；U>0。初始n=1故U=V，主实验无中途流时固定 | U不是ETF整数份额，不向整手取整，也不截成固定小数制造资金流收益 |
| n、H_n、DD、权重与目标偏离 | 保留精确比值/原始分量和出处，资格比较用第3节交叉乘；允许展示时生成小数 | 不用百分数显示值、固定epsilon或浮点近似替代严格阈值 |

规范十进制字符串使用可选负号、十进制整数与可选小数部分，不含千位分隔、百分号、NaN、Infinity或科学计数法；单位/方向另列。来源如使用科学计数法，适配层可精确展开并保留原文。规范比较时去无意义前导/尾随零、负零转零；展示仍可保留来源精度，报价按tick显示而不套金额两位规则。整数也用十进制字符串传递，防止跨语言整数精度丢失；U用分子/分母字符串对。缺失值用明确空值和原因，不用空串或“0”代替。

资源/位数限制由T-03工程选型登记，但必须覆盖本契约验收值；超出能力须返回NUMERIC_CAPACITY并阻断依赖用途，不能静默截断、环绕溢出或降成浮点。加减乘和有理数交叉比较必须精确；循环小数除法保留比值。显示金额默认2位、n默认6位、百分数默认小数点后4位，统一四舍五入、恰半远离零，并附原值可追溯；展示不能重新输入决策。

## 3. 舍入、分红与精确比较

### 3.1 仅在指定位置舍入

对非负金额a，研究用 `RoundCent(a)=floor(100a+0.5)/100`。原有佣金先累计再RoundCent；撤销/更正不能将负本金塞入该收费公式。任何未来冲回须反向引用原已确认金额，另定契约，不能重新舍入一遍。买入滑点向上tick、卖出向下tick；买保护上界向下、卖保护下界向上，沿用费用规格，不改候选参数。

**现金分红研究补充：**每个账户、同一稳定公司行动的登记权利总数量e，先计算理论额A_div=e×公告每份分配d，再一次计算 `D=RoundCent(A_div)`。本公式仅覆盖投资者端扣税及到账费用为0的明确情景：由对应公告证据支持，或在合成验收例中明确假设。现有[单次分红证据](../audits/2026-10-21-dividend-adjustment.md)不推广为全历史税则；非零/未知扣款须补税负及净结清契约，不能借舍入默认为零。登记时保存e，除息时确认R_d增加D；同时保存A_div、D及 `rounding_adjustment=D−A_div` 归因。该差已包含在R_d内，不额外再加一次资产或收益。无论权利分成几条来源记录或任务如何重试，舍入对象不变。

支付按已确认D结清R_d并等额增加C，因此在市价等其他条件固定时V不变。当前A是一笔合成支付，不设按多次支付重新舍入；未来实际到账不同须核对税/费/舍入/错误并另定调整，不能用小额容差直接核销。该约定是可复现研究支付假设，**未证明为中国结算或用户账户真实算法**。

规划账本同时改为 `P_ref=P−d`、`V_ref=V+q(P_ref−P)+D`，只计未入账的对应行动，D依已确定的e计算。e=q时仍需D=e×d才有V_ref=V；否则差额是可核查的研究舍入影响。P_ref继续减每份原始d，不能把账户舍入差摊回证券价格。实际应收仍只在实际生效阶段确认，不能提前增加可用现金。

### 3.2 U与高水位

合法外部净流x到分、资金流前估值可靠且V>0、U>0、V+x>0时，用精确比值 `U_new=U×(V+x)/V`，保留约分结果；n前后相等。费用独立记账。初次注资有唯一初始化身份；中途流仍使预登记“无中途流”主情景不符合，不以正确份额化掩盖实验范围改变。资金流时刻、全清户及估值不可用例外仍不在本版完整运行范围。

高水位保存其合格日末观测的V_h、U_h、估值/事件引用，表示H_n=V_h/U_h，而不是只存一个被舍入的n。新高条件为 `V_t×U_h > V_h×U_t`；相等保留原高水位出处。初始化纳入，开盘不更新正式高水位；更正可在有版本的新运行重算，普通重启、改模型、入金不重置。

### 3.3 阈值与候选比较

仅在输入合格且分母正时比较；以下乘积如含U有理数，先乘正分母化为整数比较，不做近似除法：

- DD严格超过k%（k=30/35/40）：`100×V_t×U_h < (100−k)×V_h×U_t`。恰等于不算超过；开盘DD显示仍按max(0,...)，不因开盘新高改变日末H_n。
- E=qP时，权重≤75%：`4E≤3V`；权重≥85%：`20E≥17V`。普通预算的T+Z≤W同样按精确金额比较。
- 比较80%目标偏离时，候选i优于j当且仅当 `abs(5E_i−4V_i)×V_j < abs(5E_j−4V_j)×V_i`。V_i/V_j必须为正，同值沿用额度规格先更少预计损耗、再更少绝对份数的确定性规则；开盘固定单必须严格优于不交易。
- V≤0、U≤0、价格/权利未知等先输出异常/UNKNOWN，不能仍算一组精确比例。不存在“离阈值很近就放行”的通用容差。

## 4. 事件身份、记录与字段

### 4.1 三种身份

来源记录说明“哪里取得哪份证据”；经济对象标识同一订单/成交/行动/交收义务/减险目标；内部业务键说明该对象的哪个动作。内容相同不代表同一次成交，URL不同也不代表两次分红。来源别名与行动关联须有证据；无法识别是否同一事件时暂存/阻断，不靠重复入账消解未知。

| 记录类型 | 当前A最小业务键，在run_id/account_id范围内唯一 |
| --- | --- |
| 初始化／外部流 | INIT固定槽位；外部流另有稳定flow_id，不能按重试新建初始化 |
| 意图／订单 | task_id、decision_batch_id、security_id、action_role；A同批次同证券冲突先按既有优先级消解，不靠再生成随机ID放两单 |
| 增量成交 | fill_id，关联order_id及单次模拟执行尝试；模拟生成器重放须保留同一fill_id |
| 交收 | 原成交/义务ID、结清阶段及期次；A一笔S1结清本金和对应新增佣金，边界例的部分结清另有子期次与累计上限 |
| 公司行动 | 稳定corporate_action_id、登记/除息/支付阶段、期次；来源版本不直接成为新经济权利 |
| 风险／复审 | 观测批次及阶段，成交后观测另绑定触发fill_id以区分同阶段多次事实；风险事件incident_id/epoch；批准approval_id及指定消费批次；不同对象分别存键 |
| 减险累计 | 稳定reduction_goal_id关联全部前序grant_id；许可替换不清累计已成量 |
| 更正 | 独立correction_id、被更正对象及依据；不得以新来源版本直接再生成同一步资产事件 |

业务键保存为结构化字段组，避免字符串拼接碰撞；event_id是不可变内部引用，可在首次接纳时生成并随键永久保存。其具体编码/UUID方案由T-03定，不能改变业务唯一性。按新规则或新输入重做研究使用新run_id并关联原运行；恢复同一运行保持全部键与累计状态。

### 4.2 公共事件封套

| 字段组 | 必填与含义 |
| --- | --- |
| 身份／版本 | schema_version、run_id、account_id、event_id、event_kind、结构化business_key；涉及证券/订单/行动/许可时相应稳定引用必填，否则显式不适用 |
| 经济内容 | 数量/价格/本金/费用/币种/单位、增量与累计标志、父事件/义务引用、规则版本；字段适用性由事件类型定义，不接收未声明的经济字段 |
| 时间 | economic_date及阶段/精度；有真实时分证据才填economic_at。usable_at与其证据/历史假设标识；实际received_at、recorded_at另存，不冒充历史发布时刻 |
| 决策／依赖 | information_cutoff、decision_batch_id、输入manifest引用、前置事件、expected_state_seq（会改变账户/权限的命令）；收到记录不等于已准入或可提交 |
| 提交／结果 | 成功后单调account_state_seq、处理结果、主/全部原因、受影响作用域、证据引用；未成功不伪造已提交序号 |
| 修订／审计 | 原始内容引用与哈希、规范经济内容版本、更正/替代关系、到达记录；无原始字节须明确未保存，不能把摘要当原件 |

账户内各成功原子状态变更取得一个顺序号，包含账本、预算和权限变化；它表示提交顺序，不伪装经济先后。来源收取日志独立，重复到达不递增经济状态。规范经济内容比较按schema处理数值等价形式，包含经济语义及对象引用，排除每次抓取时间等到达元数据；支持同一事实的来源证据列表可追加，不因此重记资产，但决策已封存的输入manifest不可替换。原始字节哈希单独保存。逐事件字段/类型/必填/约束在联合冻结前完成；机器可执行schema文件在获准实现后生成，不以此封套冒称所有来源适配已就绪。

## 5. 重复、事务与顺序

### 5.1 先判身份，再改状态

同业务键同规范经济内容返回已有结果，不重复记账、扣费、消费额度或释放冻结；重复检查先于旧expected_state_seq的拒绝，以支持“已提交但响应丢失”后的同键查询。相同键不同经济内容保留两份证据并产生IDENTITY_CONFLICT，不采用最后到达值、不合计两份、不把它当自动更正。首次未提交的失败尝试可以按原键续处理，但必须保留尝试记录与因果关系，不假装前次成功。

每笔成交是增量事实，含本次Δq、Δ本金与Δ佣金；保存并核对所属订单累计M/Γ。累计成交快照不是另一笔增量。现有A生成器给稳定成交身份；只有累计快照且无明细的真实提供方适配留G-14，不能先把快照总量全加进账本。

### 5.2 最小原子边界

| 动作 | 必须同成同败的状态 |
| --- | --- |
| 生成意图/预留 | 业务身份、固定订单与版本、现金F、额度Z、卖单份额占用；任一不合格不能只占一半 |
| 成交 | 事实去重记录、q/B/R_s/L、订单累计M/Γ、F/Z/T及份额冻结、减险目标累计，以及实际成本触发的风险锁/关联审批失效一起原子提交；必需风险计算不可靠则持久记录HOLD，不能留给内存中稍后补算 |
| S1／分红支付 | 结清事件、C与对应应收/应付及剩余义务；不能先让现金可用再消除应收 |
| 订单终态 | 终态及原因、未用F/Z/份额占用释放；已成本金/费用/T不返还，重放不重复释放 |
| 批准消费／风险更新 | 有效性检查、消费标志、锁/事件状态及相关失效记录；不允许先开买权限再标批准已用 |

提交前比对expected_state_seq；账户/权限已变则不按旧状态提交，重新核验原固定意图或终结，不能借并发重试扩量、延长会话或补做过期决策。单账户先串行处理；存储必须保障事务与重启后持久性，T-03选型/T-05/06故障验收证明。途中失败只能留下完整旧状态或完整新状态；提交结果不明时保持不确定及占用，按原键查证，不能用新键再做一次或直接释放。

### 5.3 阶段、依赖与截止

沿用A时间线：行动生效/相容价格准备→开盘风险观察→固定意图资格与模拟成交→收盘记录及登记权利→18:00合成资金事件→20:00封存→20:30日末估值/对账/风险→合格恢复消费→必要减险优先、合法普通规划。仅表示研究阶段顺序；开盘/收盘没有时分证据时不填假09:30/15:00。休市、非交易日支付及行动依各自契约，不靠“当前无开盘”删除现金事实。

每个阶段先满足父事件/义务和权利依赖，独立且可交换的事件才可按稳定键排序；影响权利、金额或许可的先后不明则MISSING_PREDECESSOR/TIME_AMBIGUOUS，不能用文件行号或容器遍历碰巧决定。交收先到须暂存，不增购买力；依赖补齐后仍核真实/研究生效时点，不能提前结清。

输入manifest固定截止前准入的来源/规则/账户状态引用；20:00:01才可用不能塞进20:00输入。截止后新获知的账户/安全事实照实保存并处理，可否决旧订单；若改变当批次依赖而使封存状态不再可靠，则跳过受影响决策并留因，不延长截止到20:30、不追补旧成交。接收事实不等于给策略新增信息交易权限。

## 6. 迟到、更正与失败输出

当前A合成研究以冻结manifest回放，未知或矛盾事件使相关批次/结果不可认证；不能只删坏日或继续出一条看似连续合格净值。输入或算法更正创建新快照/新run，关联旧运行与失效原因，保留旧订单/输出。规范确认后的源修订按[历史时间规则](../ASOF_DATA_POLICY.md)使用，不能让当时策略提前知道；原历史更正研究与当时可知研究须分开标记。

未来真实已发生的成交，即使意图过期、已请求撤单或与额度不符，也不能按“拟交易拒单”丢弃。保存可靠事实并对账，实际超界如实暴露；无法确认的回报先保存原证据、HOLD待核，不能猜一笔完整账。实际补记/冲正、累计转增量及撤单竞态仍须G-14和T-13独立设计/验收，本版没有实现这些接口。

| 主类别／最小原因码 | 处理及开发消费 |
| --- | --- |
| APPLIED／DUPLICATE | 首次原子成功或返回已处理结果；无第二次经济副作用 |
| NO_ACTION／WAIT_RESOURCE | 未触发、整手目标已完成或现金/额度/可卖量暂不足分别留明细；任务不因等待冒称完成，不自动扩大预算 |
| ORDER_REJECTED／ORDER_EXPIRED | 固定单价格保护/目标不改善/风险禁买等合法拒绝，或指定会话到期；原子终结及释放未用占用，任务依合法批次重评 |
| INPUT_INVALID／NUMERIC_CAPACITY | 格式、单位、tick、分母或算力范围非法；不得自动修成0/近似值，阻断相应用途 |
| DATA_UNKNOWN／IDENTITY_CONFLICT／TIME_AMBIGUOUS | 关键缺失、同键异内容或影响顺序不明；保留证据并按依赖作用域HOLD，非关键新闻不阻断A |
| MISSING_PREDECESSOR | 暂存并列前置对象；不记资金，涉及账户可靠性则HOLD，不无条件无限重试 |
| STATE_STALE／COMMIT_UNKNOWN | 旧版本命令重核固定意图；提交结果不明先按键查证，依赖该账户的新动作暂停，不能重复发新订单 |
| RECONCILIATION_FAILED／FACT_PLAN_MISMATCH | 账本不平或可靠已发生事实违背计划：保存事实/异常并HOLD，不裁剪成交或伪造余额以求通过 |
| APPROVAL_INVALID／UNSUPPORTED_EVENT | 审批无效仅拒绝该恢复/许可；不支持行动阻断其依赖用途。均不得顺手清旧风险锁，扩大权限或静默忽略经济事实 |

每次输出同时有status、primary_reason、reason_details、scope、evidence_refs和后续动作。先验证身份/输入/依赖和状态版本，当前真实风险可先拦截；固定Q、最终p和新增费可靠计算后，才核预计买后DD、现金/额度及目标改善，全部通过才提交。主原因选择可按身份/输入→状态/风险/资格→资源/目标的固定次序，但不能颠倒计算依赖。可以记录多原因，输入不可靠时不捏造DD或现金不足。合法策略拒单不等于数据故障HOLD；HOLD解除须按风险规格有证据，重试成功不自动解除其他锁。

## 8. 联合冻结与开发使用

本轮使G-01数值语义和G-06事件/失败语义有具体方案，仍不关闭整项或宣称AC-01通过。下一步用A一条含初建、分红、周度恢复、风控及故障的端到端时间线联合走查，核对每种事件必填载荷/状态转移和数据准入清单，再冻结A必要子范围；不为此等待全部个股/文本模型。

T-04落实无损解析/来源与经济对象关联；T-05落实精确账本、资金流及原子提交；T-06落实精确资格、去重/版本及权限；T-09呈现舍入归因、拒绝/等待/未知与证据；T-10登记新旧run和不可认证结果；T-11做中断/重启恢复演练。联合冻结前完成语言无关字段/类型/必填/约束；工程数值资源范围、存储选型、机器schema文件与测试路径由T-03起选型/实现后回填，不能写成已经存在。

保留缺口：实际来源唯一键/全范围规则和行动覆盖G-07、特殊行动/全清户G-01、完整适配与schema G-06、B/C排序与标签T-02、真实账户补费/冲正/撤单及尾差G-14、运行故障演练G-13。冻结技术语义不证明数据覆盖、实际成交或投资增量；仍须用户推进实现才开始写系统代码。
