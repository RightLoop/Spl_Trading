# 历史可用时间与版本准入规则

日期：2026-10-21，Asia/Shanghai。状态：**研究默认与审计规范草案**，用于细化[数据要求](DATA_REQUIREMENTS.md)，尚未实现数据管线，也未冻结正式实验的周度截止和成交时刻。它不改变用户的投资政策。

## 1. 为什么先确定这件事

历史研究要回答的是“用当时已经知道的信息，能否作出更好的决策”。同一报告期可以先后有不同的披露值；同一份指数调样公告也有公开日和生效日。只保存日期和最终数值，会丢掉这两种区别。

本规则采用按历史知识时点查询的原则，通常称为 point-in-time（PIT）。它不是某个接口的认证标签，而是需要逐项证据支持的性质。2026-10-15 已取得的[财报更正反例](audits/2026-10-15-financial-revisions.md)和[周度成分快照](audits/2026-10-15-hs300-constituents.md)，说明目前必须补齐这层约束。

## 2. 最小记录：内容、事实时间、获知时间分开

| 记录 | 必须保留的含义 | 不能代替它的东西 |
| --- | --- | --- |
| 对象与内容 | 证券身份、报告期/事件、指标、范围、原值、单位、规范化值 | 只保留股票简称或一个浮点数 |
| 原文版本 | 公告 ID、URL、文件内容校验值、原文定位、来源类型 | 仅文件名或“最新年报” |
| 版本关系 | 原版、更正、重述、补充、撤回；替代的对象和字段范围 | 每次请求覆盖同一期的一行 |
| 事实时间 | 报告期间；指数成员生效起止；公司行动生效日 | 网站采集时间 |
| 公开时间证据 | 原始时间字段、来源、精度、时区，以及能证实的时间范围 | 文件夹日期、数据库更新日或 PDF 封面月份 |
| 实际获取与处理 | 请求/接收时间、文件版本、校验和抽取完成时间 | 把今天下载伪装为当年已经采集 |
| 使用判定 | 允许进入哪个历史决策批次、采用哪条规则、缺失/冲突原因 | 看到有一个日期列便自动准入 |

文件校验值只能证明所保存内容的身份；不能单凭它证明文件当年已经公开，或从发布至今从未被替换。官方原文件、官方目录、正文回述和提供方表格各自保存，不把证据层级混成一个字段。

## 3. 时间精度不足时如何处理

先判断证据支持什么，再设处理延迟。所有时刻使用明确的时区。API 的 `00:00:00` 和毫秒时间戳，即使格式精细，也可能只是在表示一个日期。

| 实际证据 | 研究默认处理 | 证据边界 |
| --- | --- | --- |
| 可信原始来源说明该版本在某时刻公开，且字段语义已经核验 | 保存原始精度，加入预先约定的处理延迟后，进入下一个符合条件的决策批次 | 仍不代表本系统在当时实际收到 |
| 可确认该版本在日期 D 公开，但无具体时刻 | 保存为日期级；以 D 当天结束作为保守公开上界，再加入处理延迟；不得认定 D 开盘前已知 | 不是声称实际在午夜发布；不自动指定下一开盘成交 |
| 只能证实某版本不晚于日期 D 已公开，不能证实首次公开日 | 标为“截至 D 已公开”的上界证据；从 D 结束加同一预登记处理延迟后，考虑纳入符合条件的决策批次 | 可以支持较晚使用，不能用于精确公告反应研究 |
| 只有报告送出日期、文件路径、封面、转载或数据商更新日期 | 分别保留原义；补充公开证据，不能直接当已认证发布时间 | 多个弱日期相同也不自动升级为精确时点 |
| 完全无法约束该版本何时公开 | 不准入依赖该值的正式历史结论；可保留展示和探索用途 | 任意加 90 天不能补回缺失版本 |

“D 当天结束”在存储时可表示为下一自然日 00:00 的边界，但须同时保留“日期级上界”的标签。日历、周度信息截止、处理延迟、节假日安排和最早成交时间仍在[实验规格](DEMO_SPEC.md)中另行冻结。保守延迟只能降低提前使用的风险，不能证明来源有完整版本，也可能损失真实的早期信息价值。

历史重建与前瞻运行必须分开：重建可根据可靠的历史公开证据形成假设的可用批次；前瞻决策则必须等待实际采集、检查和必要抽取完成。网络上早已存在的信息，如果系统尚未处理完成，也不能用于已经结束的决策批次。

## 4. 不同数据采用不同的生效规则

### 财务值：按当时公开的版本选择

对同一公司、同一报告期、同一字段和会计范围，选择在信息截止前已经可用、且版本关系明确的记录。更正后保留原记录，并从更正版本可用的批次起更新。不能改写此前保存的特征、预测或交易记录。

不同修订未必替代整份报表：披露指标更正、报表金额重述、后续年报比较期调整须分别标注。更正公告本身可以是字段级证据，不必假定每次都会重新发布完整年报。计算同比或累计差分时还须核对会计口径；不能把两份各自已公开但口径不一致的数字机械相减。

发现当年的原报有错误，不要求模型盲目采用错误数字。可以按事先固定的异常规则将特征置缺失，或用当时可得基础科目按固定公式另算。**不能因为后来知道哪份报告被更正，才选择性删除当年的差样本。** 后来披露的“曾经有错”本身也是后来信息。

### 指数成员：公开与生效是两个条件

成员进入研究池，既要有证据支持当时已经获知，也要达到公告规定的生效时点。提前宣布下周调入，不代表本周已属于指数；提供方本周尚未更新，也不代表官方调整没有生效。

采用公告重建路线时，需要可核实的初始名单与此后所有相关定期、临时变更；也可以采用经核验覆盖、版本和时点的历史成员表。当前周快照只能用于抽查或有标签的近似。不能把下周快照反向填回本周，也不能用未来名单推测未知生效日。公告事件可以成为另一个事先定义的特征，但它与“当前成员”是不同字段。

调出指数、暂停交易和退市是不同事件。调出不意味着模型持仓自动成交；已有仓位如何处置仍受交易可行性、共同额度和冻结的退出规则约束。股票池有效性和交易可执行性分别检查。

### ETF 持仓：披露不等于当天真实仓位

已公开的定期报告只证明某观察日的披露持仓；之后的组合只能称基于该披露的估计。最新一份已公开年报也不能成为每一天的精确实际持仓。报告期、版本公开时间、覆盖范围、补充来源和衍生工具分别保存，具体要求见[ETF 专题](audits/2026-10-15-etf-holdings-followup.md)。

## 5. 数据准入按用途判定

| 用途 | 需要满足什么 | 证据不足时 |
| --- | --- | --- |
| 人工阅读、抽取教学 | 清楚标出来源、版本和不确定性 | 可以继续，但不能伪装成历史实时推送 |
| 正式历史预测特征 | 内容、口径、版本和不晚于截止的可用性都能追溯 | 禁用相关特征或降为探索；不能静默删掉困难股票 |
| 正式历史成员筛选 | 初始名单与事件链可核验，或经独立核验的历史成员表能支持所需日期和当时可用性 | 限定到有证据的区间，或只做明确标注的工程演示 |
| 组合约束与模拟执行 | 交易状态、成本、持仓及约束所需的暴露口径可信 | 阻断依赖该项的判断，不能把未知敞口记零 |
| 前瞻记录 | 实际获取、处理完成和决策时间可验证 | 记录延误与跳过，不追补“本来会交易”的收益 |

未知不统一填零：未公告、版本缺失、接口失败、不适用和真实零值分别记录。缺失回退规则须提前固定，并按证券、年度、行业、退出/更正类型报告覆盖情况，避免只保留容易取得的存续公司。

## 6. 三组实验如何公平

- A、B、C 共用市场日历、价格/公司行动、账本、成本和时序规则；A 是固定 ETF 基础组合，没有必要为它制造不存在的个股财报输入。
- B、C 共用个股研究池、财务版本规则和缺失处理。比较 C 相对 B 时，不能让 C 读到更正原文，却让 B 永久保留已经过时的数值。
- B、C 同步的是共有数值字段的版本与可用规则；C 仍可增加原文中的语义特征，不要求 B 获得 C 的全部文本输入。抽取错误和延时另测，不把不公平的信息时间差叫作文本增量。
- 正确的输入时点不等于消除了 LLM 预训练记忆污染；历史 C 仍须保留该限制，并由未来冻结后的前瞻记录提供更强证据。
- 未来实际收益作为预测标签本来发生在信号之后；限制是训练时标签必须已成熟。不能误把“输入不得看未来”解释为标签也只能包含过去收益。

## 7. 正式冻结前必须完成的记录

1. 明确各候选字段的公开时间证据、精度、版本覆盖和具体可用区间。
2. 确定周度信息截止、处理延迟、假期顺延、成交与标签端点；把假设与实测分别保存。
3. 固定冲突、错误原报、缺失和事件链中断的处理，给出无法进行正式结论的范围。
4. 保存一次历史决策的可审阅证据表：当时看见哪一版、为何可用、哪些输入被拒绝。现在只制定规格，不运行回测。

本规则能够防止已知类型的误用，不能凭文档保证没有遗漏。下一步应将有限案例扩展为覆盖清单；全历史准入、特征冻结、系统实现仍是后续工作。
