# 文档地图与维护结构

更新：2026-11-03。用途：把已有讨论定位到开发活动。2026-10-21 清点基线为 **28 份 Markdown、10 份 JSON**；下表覆盖该38份、当日新增的四份开发文档，以及后来新增的数据/账本、费用/跳空保护、额度/再平衡与风险状态/恢复规格。2026-10-28仅在既有账本规格中补充时序。LICENSE是仓库许可证，不计入讨论文档；它不替代第三方代码、数据和模型的许可核查。

本文件管理“去哪找、何时用、产生什么”，不复制参数或维护第二套任务状态。结论状态按条款判断，不能因文件写完就把整份草案标成已确认。状态含义见[工作流程](WORKFLOW.md)，模块与需求 ID 见[开发基线](DEVELOPMENT_BASELINE.md)，阶段与 T/AC 见[开发计划](DEVELOPMENT_PLAN.md)。

## 4. 哪份文档负责哪类定义

| 信息类型 | 主责位置 | 其他文档如何使用 |
| --- | --- | --- |
| 用户目标、范围 | PROJECT_CHARTER；决定出处在 DECISIONS | 基线给 R ID，地图和计划只回链 |
| 资金分母、账户政策、再平衡/风险原则 | INVESTMENT_POLICY | 实验和未来契约引用同一版本；发生偏好变化先修此文 |
| A 研究费用、分笔计费及跳空保护技术契约 | FEES_AND_GAP_PROTECTION；原则仍由 INVESTMENT_POLICY/DEMO_SPEC 定义 | 账本和撮合引用同一场景版本；官方费率与个人账户事实另附证据，不在索引复制完整公式 |
| 周度额度与 A 再平衡完成算法 | WEEKLY_QUOTA_AND_REBALANCE；偏好与例外原则仍由 INVESTMENT_POLICY 定义 | 订单预占/实际消耗及小额报告使用同一版本；现金预留引用费用规格，风险权限引用风险草案并待联合冻结，不以额度通过代替其他约束 |
| 风险状态、暂停与恢复契约 | RISK_STATES_AND_RECOVERY；风险偏好和用户决定仍由 INVESTMENT_POLICY/DECISIONS 定义 | 订单检查、人工复审、历史实验与未来运行使用同一权限规则；状态恢复不清高水位，不把研究候选写成已批准操作权限 |
| 实验组、期限、切分、比较标准 | DEMO_SPEC | 理论文解释原因，任务负责落实；不从理论叙述另选常量 |
| 字段/单位/质量与公司行动数据 | DATA_REQUIREMENTS | 后续详细契约承载类型/精度，主题文保留原则并链接契约 |
| 历史时间、版本与可得性 | ASOF_DATA_POLICY | 数据字典、特征卡和运行时间线引用同一语义 |
| 某种数据允许哪个用途 | DATA_USE_ADMISSION | 运行清单逐项声明范围与证据，不能只写“数据已通过” |
| 实际观察、论文/规则来源 | 日期审计与 REFERENCES | 规范引用证据和限制；不把来源内容当用户已确认参数 |
| 工作方式和状态定义 | WORKFLOW；AGENTS 保留必做规则 | 本地图不维护第二套流程 |
| 需求与模块索引、缺口、任务结果 | DEVELOPMENT_BASELINE、GAPS_AND_CONFLICTS、DEVELOPMENT_PLAN 各司其职 | PROJECT_STATE 只写当前摘要；实际代码和测试位置只在追溯台账维护 |

新证据与旧规则冲突时，先判断是事实纠错、范围改变还是偏好改变；按 WORKFLOW 更新主责文件、决定和受影响任务。不能简单以“文件日期较新”推翻用户明确要求。
